FH6 Session Probe

A small, open-source Windows diagnostic for researching automatic session detection for a Forza Horizon 6 proximity voice-chat project.

No injection No game-memory reading No gameplay modification No packet payload capture Plain PowerShell

What is being tested?

The current question is simple: if two PC players are already in the same normal FH6 freeroam session, can both PCs independently expose the same stable session or network fingerprint?

If yes, a future proximity voice client could use that fingerprint only for discovery, while voice itself runs externally.

How the tester works

Recommended 1-minute test

1

Launch FH6

Join the same normal freeroam session as the other tester and make sure you can actually see each other's cars.
2

Extract + run

If you downloaded a ZIP, Extract All first. Then double-click RUN FH6 SESSION TESTER.cmd. Administrator permission is requested because Windows Packet Monitor requires elevation.
3

Detect the game

Click Detect Running. This is the preferred path because it identifies the live FH6 process directly.
4

Capture

Start capture, remain in the same session for roughly 45–60 seconds, then mark ONLINE_FREEROAM_A.
5

Build the bundle

Click Stop + build bundle. The tester creates a Capture_..._SHARE.zip.
6

Send only the share ZIP

The raw ETL stays on your PC and is not included in the share bundle.

If auto-detect does not work

Use Choose Folder as the fallback.
Select the actual FH6 install folder. The tester searches that folder for the game executable and uses it to locate FH6-related files. You still need FH6 running before capture starts.

This fallback exists because Windows Store / Game Pass installs can sometimes hide or protect the executable path from ordinary process inspection. Auto-detect is still recommended whenever it works.

Why Administrator permission?

Windows Packet Monitor (pktmon) needs elevation for this network-flow capture. The probe uses metadata flags only. It does not enable the raw-packet-byte flag and does not inspect packet contents.

Before testing

Preflight

Run PRE-FLIGHT CHECK.cmd to check PowerShell, WinForms, networking cmdlets, Packet Monitor, FH6 process state, and capture-folder write access.

Repository tests

Run RUN SELF TESTS.cmd to syntax-check the PowerShell files, verify capture safety invariants, and smoke-test ZIP creation.

Important: passing the offline tests proves the scripts parse and the local smoke/safety checks pass. It does not prove that the FH6 session fingerprint is shared across two real players. That is exactly what the multiplayer test is for.

What gets shared?

Included

A capture manifest, probe timeline, FH6/Xbox/Gaming-related socket/process snapshots, FH6 text/config keyword hits, and Packet Monitor flow metadata when available.

Not included

Raw ETL capture, packet payloads, game memory, game modifications, or automatic uploads.
